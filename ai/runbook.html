First, the picture in your head

3 min · nothing to type

Three separate places are involved, and mixing them up is the single biggest source of confusion. Keep them straight:

PlaceWhat it isWhere your course code goes
Windows Your normal desktop. Chrome, Explorer, C:\Users\... No
WSL Ubuntu A real Linux running inside Windows. Its own filesystem, its own Python, its own home folder at /home/yourname (shortcut: ~) Yes — here
Google's servers Where the Gemini model actually runs. Your code sends text over the internet and gets text back No — you never install a model

One thing worth knowing now: from Ubuntu, your Windows C: drive appears as /mnt/c/. It is tempting to put your project there so Explorer can see it. Don't. Reading many small files across that Windows↔Linux boundary is roughly ten times slower, and Git and Python both read thousands of small files. Keep the project in Ubuntu's own filesystem. You can still open it from Windows — Step 5 shows how.

Eight terminal commands, and how to paste into one

15 min

Open Ubuntu: press the Windows key, type Ubuntu, hit Enter. You get a black window ending in $. That $ is the prompt — it means "I'm waiting for a command." You type a command, press Enter, it runs.

Pasting

In this terminal, Ctrl+V may do nothing. Use Ctrl+Shift+V, or just right-click. Copy is Ctrl+Shift+C. Every code block on this page has a Copy button on the right.

The eight you need

CommandWhat it does
pwdprint working directory — tells you which folder you are currently in. Use it whenever you feel lost.
lslist — shows files in the current folder. ls -la also shows hidden files (ones starting with a dot).
cd foochange directory — go into folder foo. cd .. goes up one level. cd ~ goes home.
mkdir foomake directory — create a folder called foo.
cat file.txtdump a file's contents onto the screen.

Two habits that save hours

  • Tab completes. Type cd ~/co and press Tab — it fills in code/. Fewer typos.
  • Up arrow repeats. Press ↑ to bring back the last command instead of retyping it.

02

What that install command actually did

8 min

You ran this. Here is what each piece means.

the command you ran
curl -fsSL https://claude.ai/install.sh | bash

Piece by piece

  • curlA downloader. Fetches whatever is at a URL and prints it to the screen.
  • -fFail quietly if the server returns an error page, instead of downloading the error page itself.
  • -sSilent — no progress bar.
  • -S...but still show me real errors. -s and -S are almost always used together.
  • -LFollow redirects. If the URL moved, go to the new address.
  • |A pipe. Takes the output of the thing on the left and feeds it as input to the thing on the right.
  • bashThe shell. Given a script on its input, it runs every line of it.

So end to end: download a script from the internet and immediately execute it with your user's permissions.

The habit to build

That pattern is everywhere in developer docs and it is fine when you trust the domain — here, claude.ai is Anthropic's own. But you should never run it on a URL you haven't looked at. The safe version separates download from execution so you can read it first:

the careful way
curl -fsSL https://claude.ai/install.sh -o install.sh
less install.sh     # read it; press q to quit
bash install.sh

Apply this to anything I or anyone else hands you.

Did it work?

terminal
claude --version
claude doctor

A version number like 2.1.211 (Claude Code) means it installed. If you get command not found, the program exists but your shell doesn't know where to look. Fix it:

fix PATH
echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.bashrc
source ~/.bashrc
claude --version

Why that works

PATH is a list of folders your shell searches when you type a command name. The installer put claude in ~/.local/bin, which wasn't on the list. The first line appends that folder to the list inside ~/.bashrc — a file Ubuntu runs every time you open a terminal — so the fix sticks. source re-reads that file right now instead of making you close and reopen the window.

We'll come back to Claude Code in Step 12. Right now it's installed and that's enough.

04

Get your Gemini API key

5 min · in your Windows browser

An API key is a long random string that identifies your Google account to Google's servers. When your Python script sends a request, the key is what says "this is me, charge my quota." Treat it exactly like a password.

The clicks

  1. Open aistudio.google.com/apikey in Chrome.
  2. Sign in with your Google account. Accept the terms if prompted.
  3. Click Create API key (sometimes labelled "Get API key").
  4. If it asks which Google Cloud project to use, choose Create API key in new project. You do not need to set up billing.
  5. A long string starting AIza... appears. Click the copy icon.

Keep it on your clipboard — you'll paste it in Step 7. If you lose it, come back to the same page; the key is listed there.

Two things about the free tier

It is genuinely free and needs no card. The Flash-family models are free to call, with per-minute and per-day request caps. Those caps are fine for Sessions 1 and 2, where each exercise is one or two calls. They will start to bite in Session 3 onward, when an agent loop makes twenty calls per run — deal with that when you get there.

Free-tier prompts are used to improve Google's products. The paid tier explicitly is not. For coursework that's fine. Never point this key at your employer's data.

06

Create a virtual environment

8 min

What a virtual environment is, and why

If you install Python packages system-wide, every project shares them. Project A needs version 1 of a library, project B needs version 2, and one of them breaks. A virtual environment is just a folder holding a private copy of Python plus this project's packages. "Activating" it points your shell at that copy instead of the system one. Nothing magic — it's a folder and a PATH trick.

terminal
cd ~/code/applied-ai
python3 -m venv .venv
source .venv/bin/activate

Your prompt now starts with (.venv). That is how you know it's on.

Piece by piece

  • -m venvRun Python's built-in venv module.
  • .venvThe folder to create. The leading dot makes it hidden, which is convention.
  • sourceRun a script in the current shell so its changes stick, rather than in a child shell where they'd vanish.

Now install the three libraries you need:

terminal (with (.venv) showing)
pip install -U google-genai pydantic python-dotenv
PackageWhat it's for
google-genaiGoogle's official Gemini SDK. Arpit's exercises say "official SDK" — this is it.
pydanticDescribes the exact shape you want data in, and validates it. Session 1, exercise 2 is built on this.
python-dotenvReads your API key out of a .env file so it never appears in your code.

Remember this one thing

The virtual environment is per-terminal-window. Every new Ubuntu window, before you run any Python, do:

every new terminal
cd ~/code/applied-ai && source .venv/bin/activate

If you see ModuleNotFoundError: No module named 'google', this is almost always why. deactivate turns it off.

Store the key so you never leak it

6 min

Keys get leaked by being typed into source files that later get pushed to GitHub. Bots scan public repos for exactly this. The fix is a file that holds the key and never leaves your machine.

terminal
cd ~/code/applied-ai
nano .env

Type this line, pasting your real key after the = with no spaces and no quotes:

.env
GEMINI_API_KEY=AIzaSyXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX

Save and quit: Ctrl+O, Enter, Ctrl+X.

Now tell Git to never upload it:

terminal
nano .gitignore
.gitignore
.env
.venv/
__pycache__/
*.pyc

Save and quit the same way.

What .gitignore does

It's a list of things Git pretends not to see. .env keeps your key off GitHub. .venv/ keeps thousands of library files out of your repo — anyone can recreate them with one pip install. __pycache__/ and *.pyc are Python's compiled scratch files.

Prototype 1 — summarise a long file

25 min · Session 1, exercise 1

The assignment: "Have a file containing long text. Summarize it using your favorite LLM via its official SDK, then output the summary."

First, something to summarise

terminal
cd ~/code/applied-ai/session1/p1-summarize
nano article.txt

Paste in several paragraphs of anything — a blog post, a Wikipedia section, one of Arpit's articles. Aim for at least 500 words so the summary is doing real work. Save and quit.

The script

terminal
nano summarize.py
summarize.py
import os

from dotenv import load_dotenv
from google import genai

# 1. Read .env (walks up the folders until it finds one) into environment vars
load_dotenv()

# 2. Build the client. This object knows your key and how to reach Google.
client = genai.Client(api_key=os.environ["GEMINI_API_KEY"])

# 3. Read the whole file into a Python string
with open("article.txt", "r", encoding="utf-8") as f:
    article = f.read()

print(f"Read {len(article)} characters, roughly {len(article) // 4} tokens.\n")

# 4. Build the prompt. The delimiters make it unambiguous to the model
#    where your instruction ends and the data begins.
prompt = f"""Summarise the text between the --- markers in exactly 5 bullet points.
Be specific. Do not add anything that is not in the text.

---
{article}
---"""

# 5. Send it. This is the network call.
interaction = client.interactions.create(
    model="gemini-3.8-flash",
    input=prompt,
)

# 6. Print what came back
print(interaction.output_text)
run it
python summarize.py

What just happened

Your script turned a string into an HTTPS request, Google ran a model over it on their hardware, and sent text back. Nothing ran locally except your six lines. The len(article) // 4 line is a rough rule of thumb — English averages about four characters per token, and tokens are the unit models are billed and rate-limited in. Getting a feel for that number now will pay off in Session 2 when you start worrying about context windows.

If the model name errors

Model IDs change every few months. If you get a "model not found" error, list what your key can actually reach and swap the name in line 5:

terminal
python -c "
from dotenv import load_dotenv; load_dotenv()
import os
from google import genai
c = genai.Client(api_key=os.environ['GEMINI_API_KEY'])
for m in c.models.list(): print(m.name)
"

Pick any name with flash in it — those are the free ones.

Now actually learn something from it

Don't stop at "it printed something." Change one thing at a time and watch what moves:

  • Ask for 3 bullets instead of 5. Does it obey exactly?
  • Remove the --- markers. Does the model start summarising your instruction as well as the article?
  • Delete "Do not add anything that is not in the text." Does it start inventing?
  • Run the identical script twice. Is the output identical? Why not?

Write the answers in session1/notes/. That file is what you'll actually revise from.

Prototype 2 — force the output into a schema

30 min · Session 1, exercise 2

Why this exercise exists

Prototype 1 returned prose. Prose is useless to the next program in a pipeline — you can't reliably pull "day 3's activities" out of a paragraph. Real systems need the model to emit a fixed shape. You declare that shape as a Pydantic class, hand its JSON schema to the API, and the model is constrained to produce matching JSON. This is the single most load-bearing technique in the whole course.

terminal
cd ~/code/applied-ai/session1/p2-itinerary
nano itinerary.py
itinerary.py
import json
import os

from dotenv import load_dotenv
from google import genai
from pydantic import BaseModel

load_dotenv()
client = genai.Client(api_key=os.environ["GEMINI_API_KEY"])

# ---- 1. Declare the shape you want ------------------------------------
# Each class is one JSON object. Types are enforced.

class DayPlan(BaseModel):
    day: int
    activities: list[str]

class Itinerary(BaseModel):
    destination: str
    trip_duration_days: int
    budget_category: str
    top_attractions: list[str]
    daily_plan: list[DayPlan]

# ---- 2. Ask for it -----------------------------------------------------

prompt = (
    "Pick any random source city and any random destination city in the world. "
    "Build a travel itinerary using only your own knowledge. "
    "budget_category must be one of: budget, mid-range, luxury."
)

interaction = client.interactions.create(
    model="gemini-3.8-flash",
    input=prompt,
    response_format={
        "type": "text",
        "mime_type": "application/json",
        "schema": Itinerary.model_json_schema(),
    },
)

# ---- 3. Validate what came back ---------------------------------------
# If the model returned the wrong shape, this line raises. That is the point:
# you find out here, not three functions later.

trip = Itinerary.model_validate_json(interaction.output_text)

# ---- 4. Use it like a normal Python object ----------------------------

print(f"{trip.destination} — {trip.trip_duration_days} days ({trip.budget_category})")
print(f"Top attractions: {', '.join(trip.top_attractions)}\n")

for day in trip.daily_plan:
    print(f"Day {day.day}:")
    for activity in day.activities:
        print(f"   • {activity}")

print("\n--- raw JSON ---")
print(json.dumps(trip.model_dump(), indent=2))
run it
python itinerary.py

The three lines that matter

  • Itinerary.model_json_schema() turns your Python classes into a JSON Schema document — the machine-readable description of the shape. That's what the API understands.
  • response_format={...} tells Gemini to constrain its output to that schema rather than writing free text.
  • Itinerary.model_validate_json(...) parses the returned JSON string and checks every field and type, giving you back a real Python object with autocomplete and trip.daily_plan[0].day access.

Experiments worth running

  • Add a field the model can't possibly know, like flight_number: str. Does it invent one? What does that tell you about trusting schema-constrained output?
  • Change trip_duration_days: int to trip_duration_days: str. Watch the output type change.
  • Remove response_format entirely but keep asking for JSON in the prompt. Run it five times. How often does it come back as valid, parseable JSON? This is the difference between prompting for a format and constraining to one.

Prototype 3 — tool calling

35 min · Session 2, exercise 1

The mental model — read this before the code

The model cannot fetch the weather. It has no internet, no clock, no database. What it can do is read a description of a function you own and reply: "I'd like you to run get_weather with city="Jaipur"."

So a tool call is two round trips, and your code does the actual work in between:

  1. You send the question plus a description of the tools available.
  2. The model replies with a function_call — a name and arguments. It has not answered your question yet.
  3. Your Python runs the real function. This is the part people miss: the model never executes anything.
  4. You send the result back.
  5. The model writes the final sentence using that result.

Every agent framework you'll meet in Session 3 is this loop, wrapped. Understand it here and Session 3 becomes easy.

terminal
cd ~/code/applied-ai/session2/p1-weather-tool
nano weather.py
weather.py
import json
import os
import random

from dotenv import load_dotenv
from google import genai

load_dotenv()
client = genai.Client(api_key=os.environ["GEMINI_API_KEY"])
MODEL = "gemini-3.8-flash"

# ---- 1. The real function. Fake data, real behaviour. -----------------

def get_weather(city: str) -> dict:
    random.seed(city)          # same city always gives the same answer
    return {
        "temperature_c": round(random.uniform(15, 42), 1),
        "condition": random.choice(["Clear", "Haze", "Light rain", "Cloudy"]),
        "humidity": random.randint(30, 90),
    }

# ---- 2. How you describe that function TO the model -------------------
# This is just a dict. The model reads the descriptions to decide when
# to call it and what to pass. Write them for a human; that's who reads them.

get_weather_declaration = {
    "type": "function",
    "name": "get_weather",
    "description": "Get the current weather for a city.",
    "parameters": {
        "type": "object",
        "properties": {
            "city": {
                "type": "string",
                "description": "Name of the city, for example Noida",
            },
        },
        "required": ["city"],
    },
}

# ---- 3. Round trip one: ask, and offer the tool -----------------------

first = client.interactions.create(
    model=MODEL,
    input="Pick one random city in India and report its current weather.",
    tools=[get_weather_declaration],
)

fc = next(s for s in first.steps if s.type == "function_call")
print(f"[model wants to call] {fc.name}({fc.arguments})")

# ---- 4. YOUR code runs the function -----------------------------------

result = get_weather(**fc.arguments)
print(f"[your code returned]  {result}")

# ---- 5. Round trip two: hand the result back --------------------------

final = client.interactions.create(
    model=MODEL,
    input=[
        {
            "type": "function_result",
            "name": fc.name,
            "call_id": fc.id,
            "result": [{"type": "text", "text": json.dumps(result)}],
        }
    ],
    tools=[get_weather_declaration],
    previous_interaction_id=first.id,
)

print(f"\n[final answer]\n{final.output_text}")
run it
python weather.py

The bits of syntax you may not have seen

  • next(...)Takes the first item from a generator. Here: the first step in the response whose type is function_call.
  • **fc.argumentsUnpacks a dict into named arguments. {"city": "Jaipur"} becomes get_weather(city="Jaipur").
  • call_idLinks your result back to the specific request. Matters once the model asks for several tools at once.
  • previous_interaction_idTells Google to continue the same conversation rather than start fresh, so it still remembers the question.

Experiments worth running

  • Change the description to something vague like "gets data". Does the model still call it correctly? This is why tool descriptions are prompt engineering.
  • Ask "What is 17 times 23?" while offering only the weather tool. Does it call the wrong tool, or correctly decline to use one?
  • Make get_weather raise an exception. What does your script do? Now think about what a production agent would need to do instead.
  • Ask for the weather in two cities. Look at first.steps — how many function_call steps come back? Your code currently handles one.

When it asks for a password

GitHub stopped accepting account passwords over HTTPS. You need a Personal Access Token instead:

  1. github.com → click your avatar → Settings
  2. Scroll to the bottom of the left sidebar → Developer settings
  3. Personal access tokens → Tokens (classic) → Generate new token (classic)
  4. Name it "wsl", set an expiry, tick the repo scope
  5. Generate, and copy the token — it is shown exactly once
  6. Back in the terminal: username is apsy3677, password is the token

To stop being asked every time: git config --global credential.helper store (saves it in a plain file in your home folder — acceptable on your own machine, not on a shared one).
